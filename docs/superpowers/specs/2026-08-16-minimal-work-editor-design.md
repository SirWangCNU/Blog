# 极简作品编辑器设计

## 目标

把当前多字段作品表单改成接近写文章的编辑体验。作者只需要填写作品标题和项目正文，并能在正文光标位置上传、插入图片。

## 页面结构

- 顶部保留“新建作品/编辑作品”标题和返回作品列表入口。
- 编辑区只显示“作品标题”和“项目正文”两个主要输入区域。
- 正文工具栏提供“插入图片”“编辑”“预览”。
- 底部保留“保存草稿”和“立即发布”。
- 分类、标签、GitHub、演示地址、文档地址、精选、独立封面和截图图库不再显示。

## 数据兼容

- 不改变现有 `Work` 与 `WorkInput` 数据结构，避免旧作品数据丢失。
- 编辑旧作品时，隐藏字段沿用原值。
- 新作品的隐藏字段使用安全默认值。
- 保存时从 Markdown 正文去除语法后提取简短摘要；正文为空时使用作品标题作为摘要。
- 插入第一张正文图片时，如果作品没有封面，则自动把该图片设为封面。

## 正文插图

- 点击“插入图片”打开系统文件选择器，仅选择图片。
- 图片继续通过现有 `/api/upload` 上传到 `works` 目录。
- 上传成功后，在当前光标位置插入 `![图片说明](图片地址)` Markdown。
- 默认图片说明取文件名去掉扩展名后的文字。
- 上传期间按钮显示处理中并禁用；失败时显示明确错误消息。
- 插入后恢复编辑状态，并把光标放到 Markdown 图片语法之后。

## 验证

- 组件测试验证只呈现标题和正文，不再呈现旧字段。
- 组件测试验证图片上传后 Markdown 被插入，并自动成为首张封面。
- 组件测试验证提交载荷自动生成摘要并保留草稿/发布行为。
- 运行现有全量测试、后台范围 Lint、生产构建和后台路由检查。

## 非目标

- 不引入富文本编辑器或新的编辑器依赖。
- 不修改存储方式、作品公开页结构、登录系统或上传接口安全策略。
- 不删除旧作品中的隐藏字段。
