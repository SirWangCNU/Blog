# SQLite 管理员认证与博客内容持久化设计

## 目标

为个人博客增加单管理员登录能力，并将文章、作品、笔记和媒体元数据统一持久化到 SQLite。首页提供一个低调的小按钮通往管理台；未登录用户进入登录页，已登录管理员直接进入控制台。

本次同时完成现有内容迁移与博客文章管理，使管理员可以在后台新建、编辑、保存草稿、发布和删除文章，而不再通过修改源码发布内容。

## 范围

本次包含：

- 单管理员初始化、登录、退出和会话过期。
- 后台页面、草稿数据和写接口的统一鉴权。
- 文章、作品、笔记及媒体元数据的 SQLite 存储。
- 现有源码文章、作品 JSON、笔记 JSON 和上传文件的一次性迁移。
- 后台博客文章列表与 Markdown 编辑流程。
- 公共页面改为从 SQLite 读取已发布内容。
- 首页增加通往管理台的小按钮。
- 持久化目录、备份方式和部署配置说明。

本次不包含多管理员、公开注册、找回密码、角色权限、富文本编辑器、对象存储或在线数据库服务。

## 技术选型

使用 Node.js 22 及以上版本内置的 `node:sqlite` 直接访问 SQLite，不引入 ORM 或额外原生数据库依赖。数据库默认位于 `data/blog.sqlite`，可通过环境变量覆盖持久化数据目录。SQLite 与当前单机 PM2 部署方式匹配，部署时必须保留数据库文件。

密码哈希和令牌生成使用 Node.js 内置 `crypto`：密码采用随机盐与 `scrypt`，会话令牌采用密码学安全随机字节。浏览器仅持有原始令牌，数据库仅保存令牌的 SHA-256 哈希。

## 数据模型

### 管理员

`admins` 表只允许存在一个有效账号，字段包括标识、唯一用户名、密码哈希、密码盐、创建时间和更新时间。应用不提供注册入口。

### 会话

`admin_sessions` 表记录令牌哈希、管理员标识、创建时间、到期时间和最后使用时间。退出登录时删除当前会话；验证时拒绝并清理过期会话。

### 文章

`posts` 表保存唯一 slug、标题、摘要、Markdown 正文、分类、标签 JSON、阅读时长、状态、发布时间、创建时间和更新时间。状态只允许 `draft` 与 `published`；公共页面仅查询已发布文章。

### 作品

`works` 表承接现有 `Work` 数据结构，保留唯一业务标识、标题、摘要、详情、链接、标签、图库、精选状态、发布状态及时间字段。数组字段以 JSON 文本保存，并由仓储层统一序列化和校验。

### 笔记与媒体

`notes` 表保存标题、Markdown 内容和时间字段。`media` 表只保存原文件名、磁盘文件名、相对 URL、MIME 类型、文件大小和上传时间。

图片、视频等文件本体继续存放在 `public/uploads/`，不写入 SQLite BLOB。文件写入成功后才创建媒体记录；删除时同时删除媒体记录和对应文件。

## 模块边界

- 数据库模块负责连接、建表、事务与生命周期，不承载页面逻辑。
- 各内容仓储分别负责文章、作品、笔记和媒体的数据映射与查询。
- 认证模块负责密码哈希、凭据验证、会话创建、Cookie 管理和当前管理员解析。
- 页面与路由通过仓储和认证模块工作，不直接拼接 SQL。
- 输入验证放在服务边界，数据库约束作为第二层保护。

## 管理员初始化

首次部署通过 `ADMIN_USERNAME` 与 `ADMIN_INITIAL_PASSWORD` 创建唯一管理员。仅当管理员表为空时执行初始化；数据库已有管理员时忽略初始化密码，避免部署时意外覆盖现有凭据。

初始化完成并验证登录后，应从 PM2 或服务器环境中移除 `ADMIN_INITIAL_PASSWORD`。代码和仓库中不提供默认账号或默认密码。

## 登录与鉴权流程

1. 用户点击首页“后台管理”小按钮进入 `/admin`。
2. 服务端检查会话；无有效会话时跳转 `/admin/login`。
3. 登录页提交用户名和密码到认证接口。
4. 认证模块验证 `scrypt` 哈希；失败时返回统一错误，不区分账号不存在或密码错误。
5. 成功后创建随机会话，将令牌哈希和过期时间写入 SQLite，并设置 `HttpOnly`、`SameSite=Lax` Cookie；生产环境同时设置 `Secure`。
6. 登录页只接受站内相对返回路径，默认跳转 `/admin`，避免开放重定向。
7. 退出登录删除当前会话并清除 Cookie。

会话默认有效期为七天。后台页面、管理员数据查询、草稿读取、上传以及所有新增、修改和删除接口都必须在服务端验证会话，不能只依赖前端隐藏按钮。

登录接口实施基础限流。限流错误、凭据错误和服务异常使用明确但不泄露账号状态的响应。Cookie 不向客户端 JavaScript 暴露。

## 路由与页面结构

`/admin/login` 使用独立的简洁登录布局，不显示后台侧栏和工具栏。已登录用户访问登录页时直接跳转 `/admin`。

受保护后台路由使用单独的路由组布局统一执行服务端鉴权，并继续复用现有 `AdminShell`。这样登录页与后台共享 `/admin` URL 前缀，但不会互相污染布局。

现有 `/admin/blog` 升级为文章列表，支持状态筛选、编辑和删除；新增 `/admin/blog/new` 与 `/admin/blog/[id]`，编辑器使用 Markdown 文本区域，提供“保存草稿”和“发布”两个明确操作。

## 首页入口

首页 Hero 的现有操作区域增加一个尺寸较小、视觉权重低于“阅读博客”的“后台管理”按钮。按钮链接到 `/admin`，由服务端依据会话决定进入控制台或跳转登录页。

入口在桌面和移动端均可点击，具有可见焦点和清晰的无障碍名称。它不展示登录状态，也不暴露管理员账号信息。

## 公共内容读取

首页、博客列表、文章详情和作品页改为通过仓储读取 SQLite。公共查询只返回 `published` 数据；不存在或未发布的文章详情返回 404。排序规则保持现有体验：文章按发布时间倒序，作品按更新时间倒序，精选作品继续单独筛选。

现有页面组件尽量保持不变，数据结构转换集中在仓储层，避免数据库字段渗透进展示组件。

## 迁移策略

提供可显式执行的一次性迁移脚本：

- 将 `src/data/posts.ts` 中的现有文章导入 `posts`。
- 将 `data/works/*.json` 导入 `works`。
- 将 `data/notes/*.json` 导入 `notes`。
- 扫描 `public/uploads/` 并补齐媒体元数据。

迁移以 slug、作品标识、笔记标识和媒体相对路径作为稳定键，使用事务和幂等写入；重复执行不会生成重复记录。迁移报告输出新增、更新、跳过和失败数量。任一结构化内容迁移失败时回滚该批事务，并保留原始文件。

迁移验证通过前不删除旧数据。应用切换到 SQLite 后，旧文件只作为迁移来源和短期回滚依据，不再作为运行时数据源。

## 错误处理与安全

- SQL 使用参数绑定，禁止拼接用户输入。
- slug、状态、标签、文件大小和 MIME 类型在写入前验证。
- 文件路径由服务端生成并规范化，拒绝目录穿越。
- 登录表单和管理表单提供字段级错误与通用服务错误。
- 删除操作保留二次确认；数据库与文件删除失败时返回可恢复提示。
- 日志不记录密码、原始会话令牌或 Cookie。
- SQLite 启用外键约束和 WAL 模式，并设置合理的忙等待时间。

## 部署与备份

生产环境必须持久化：

- `data/blog.sqlite` 以及 SQLite 可能产生的 WAL 辅助文件。
- `public/uploads/` 下的上传文件。

部署脚本不得删除或覆盖这些路径。备份应在 SQLite 一致性快照后打包数据库与上传目录，并定期验证恢复流程。数据库文件、备份文件和管理员环境变量不得提交到 Git。

## 测试与验收

自动化测试覆盖：

- 密码哈希验证、错误密码和无默认凭据。
- 会话创建、有效验证、退出撤销和过期清理。
- 未登录后台跳转与受保护 API 返回 401。
- 登录返回路径校验和基础限流。
- 迁移脚本幂等性及原内容字段完整性。
- 文章、作品、笔记与媒体仓储的增删改查。
- 公共查询不返回草稿。
- 首页“后台管理”小按钮链接正确且可访问。
- 后台文章草稿、发布、编辑和删除流程。

最终运行完整测试、ESLint 和生产构建。人工验收包括：首次初始化管理员、登录、退出、会话过期、现有内容迁移、后台发布文章、首页读取新文章、移动端入口与登录页展示，以及重启 PM2 后数据仍存在。

## 完成标准

- 首页显示通往 `/admin` 的小型后台管理按钮。
- 未登录用户无法访问后台、草稿或写接口。
- 唯一管理员可以登录、退出并管理文章。
- 文章、作品、笔记和媒体元数据统一从 SQLite 读写。
- 上传文件保留在持久化磁盘并与媒体记录一致。
- 现有内容完整迁移且迁移可安全重复执行。
- 服务器重启和重新部署后数据库与上传文件仍然存在。
- 自动化测试、Lint 与生产构建通过。
